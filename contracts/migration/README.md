# FumaMigrationDistributor

A multi-asset Merkle airdrop distributor for the Fushuma chain migration. It
pays migrated **native FUMA** and **ERC-20** balances to holders who present a
Merkle proof generated by the snapshot toolkit
([`src/lib/snapshot`](../../src/lib/snapshot),
[`scripts/snapshot`](../../scripts/snapshot)).

> This contract is a deployment artifact for the migration. This repo has no
> Solidity build; compile and deploy it from the Fushuma contracts repo
> (Foundry/Hardhat) or Remix. It has **no external imports** and compiles
> stand-alone with Solidity `^0.8.20`.

## How it fits together

1. Run `pnpm snapshot:build` to produce `claims/<SYMBOL>.json` (a `merkleRoot`
   and per-address `{ amount, proof }`) and a `manifest.json`.
2. Deploy `FumaMigrationDistributor` on the new chain with an owner (a multisig
   is recommended).
3. Fund it: send native FUMA (`tokenTotal` of the FUMA bundle) and transfer each
   ERC-20 (`tokenTotal` of that bundle) to the contract.
4. `setRoot(asset, root)` for each asset — `asset` is the ERC-20 address, or
   `NATIVE` (`address(0)`) for native FUMA.
5. `finalizeRoot(asset)` to lock allocations before opening claims.
6. Holders call `claim(asset, account, amount, proof)`. Anyone may submit a
   claim; funds always go to `account`.

## Leaf & proof format

Identical to `@openzeppelin/merkle-tree` `StandardMerkleTree` with leaf encoding
`["address","uint256"]`:

```
leaf = keccak256(bytes.concat(keccak256(abi.encode(account, amount))))
```

Internal nodes use commutative (sorted-pair) hashing, matching OpenZeppelin's
`MerkleProof`. The distributor reconstructs the leaf from `(account, amount)` and
folds the caller-supplied proof, so a valid proof from `claims/*.json` verifies
directly on-chain.

## Security properties

- **Per-asset isolation.** Each asset has its own root and its own claimed map, so
  a proof for one asset can never be replayed against another.
- **Immutable allocations.** After `finalizeRoot(asset)`, the root cannot change.
- **No double claims.** `claimed[asset][account]` is set before any transfer
  (checks-effects-interactions) and guarded by a reentrancy lock.
- **Funds route to the entitled address.** `claim` sends to the leaf's `account`,
  not `msg.sender`, so third parties can sponsor gas without redirecting funds.
- **Non-standard ERC-20s.** Transfers tolerate tokens (e.g. USDT) that don't
  return a bool.
- **No mid-window rug.** Unclaimed funds can only be `sweep`ed after an
  owner-set `claimDeadline`, and never before.

## Owner API

| Function | Purpose |
| --- | --- |
| `setRoot(asset, root)` | Publish/update an asset's Merkle root (until finalized) |
| `finalizeRoot(asset)` | Lock an asset's root permanently |
| `setClaimDeadline(ts)` | Time after which unclaimed funds may be swept (`0` = never) |
| `sweep(asset, to, amount)` | Recover unclaimed funds, only after the deadline |
| `transferOwnership(newOwner)` | Hand control to a new owner/multisig |

## Verification of on-chain compatibility

The snapshot test-suite (`pnpm test src/lib/snapshot`) proves every generated
proof folds to its root through a mirror of this contract's `_verify`/`_hashPair`
logic. During development the compiled contract was additionally deployed in an
EVM and exercised against library-generated roots/proofs — native claims pay the
exact amount to the leaf address, and double-claim / wrong-amount / wrong-proof /
non-included-address all revert. Re-run such checks in your Foundry/Hardhat suite
before mainnet deployment.

## Suggested deployment checklist

- [ ] Snapshot built and `pnpm snapshot:verify` passes.
- [ ] Owner set to a multisig.
- [ ] Contract funded ≥ `tokenTotal` for every asset.
- [ ] `setRoot` + `finalizeRoot` done for every asset; roots match `manifest.json`.
- [ ] `claimDeadline` set to the intended end of the claim window.
- [ ] A few real proofs from `claims/*.json` claimed successfully on a testnet fork.
